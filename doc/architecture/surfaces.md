# 四个表面：单直播间 / 后台收听 / 悲鸣观测 / 灵动岛

日期：2026-11-22。状态：模型已定，按阶段落地中。
取舍与复查条件见 [0012](../decisions/0012-surface-model.md)，
观测墙本身的规则见 [watch.md](watch.md)，播放链路见 [playback.md](playback.md)。

## 一句话

产品里只有两个问题：**声音在谁身上**，**画面出现在哪**。其余都是这两件事的呈现。

四个"场景"不是四套播放器，是**一个会话集合的三个视图加一个指示器**：

| 表面 | 它是会话的什么 |
|---|---|
| 悲鸣观测 | 盒里每个会话的格子视图（可多路同时可见） |
| 单直播间 | 焦点会话的全尺寸视图 |
| 后台收听 | 焦点会话**没有任何全尺寸视图**时的状态，不是一种模式 |
| 灵动岛 | 焦点会话的指示器，形态由"焦点存在 + 当前表面"推导 |

所以 `background` 不该是一个字段，它是 `presentation(focus) == Hidden` 的推论。
同理"墙上 active"不是第二种播放，就是焦点会话被画在格子里。

## 三个正交轴

```text
S   会话集合     每间房至多一个会话（引擎 / 流 / 音量 / 播放态 / 弹幕）
F   声音焦点     标量，至多一个，或空
R   路由与分区   home / follows(streamers|subs|watch) / player
```

三个派生量，各只有一个求值点：

| 派生量 | 求值 | 现在的实现 |
|---|---|---|
| 呈现尺寸 `P(s)` | `presentSizeFor()` | 已经是唯一入口（`player_media.go`） |
| 声音归属 | `F` | 散在 `WatchActive` / `a.Volume` / `a.Playing` 三处 |
| 岛形态 | `islandFormOf()` | 已收敛成三种：时钟 / 展开 / 后台收听 |

## 组合表

| 路由 \ 焦点 | F=∅ | F=k，k 在盒里 | F=k，k 不在盒里 |
|---|---|---|---|
| home / follows 其他分区 | 岛=时钟 | 岛=头像圆；k 隐藏解码 160×90 | 同左 |
| follows/watch | 岛=时钟；全格静音预览 | 岛=展开；k 格 active + 绿点 | 墙照常；k 隐藏出声；岛=头像圆 |
| player（目标是 k） | — | 岛=展开；全尺寸 + 弹幕 | 同左 |

第三列是过去没有定义的一格，也是三个洞的来源（见下）。

## 七条不变量

凡是"X 必须 Y"都写成可执行的测试，不写在文档里当口号。

1. **至多一路出声。** 任意时刻，非 0 音量的播放器不超过一个。
2. **出声必有播放器。** `F != ""` 时，该会话的播放器非 nil 且未关闭。
3. **一个房间至多一个引擎。** 同一 `platform|roomID` 同时最多一个 `*ui.VideoPlayer`。
4. **呈现尺寸与表面一致。** 全尺寸视图 → 0,0；格子视图 → 格子物理像素；无视图 → 160×90。
5. **岛形态与实际声音归属一致。** 有声音时岛上必有那一间；没有声音时岛上不出现它。
6. **静止时无泄漏会话。** 墙不可见且用户没开「离开后继续播放」时，非焦点会话
   在 `watchReapGrace`（2 秒防抖）后全部关闭；开了就留着，那是用户认下的成本。
7. **弹幕只属于全尺寸视图。** 离开播放页即断开并清空。

## 四条操作路径与它们该有的现象

### 进 / 出播放页

| 操作 | 该有的现象 |
|---|---|
| 列表点卡片 | 卡片封面长成舞台，落地后流淡入；弹幕新连一条 |
| 墙上单击 / 点岛 | 同一元素从格子矩形连续放大到舞台；画面第一帧起就是全尺寸；不重取流 |
| 点 X / Esc，房间**在盒里** | 声音收掉，退回墙，这一格**还亮着**变静音预览 |
| 点 X / Esc，房间**不在盒里** | 彻底关闭，回上一页 |
| 顶栏 tab 离开 | 后台收听：声音不断，岛收成头像圆 |

### 墙上

| 操作 | 该有的现象 |
|---|---|
| 单击格子 | 进播放页，同一引擎 |
| hover 底栏「在墙上听」 | 焦点移过去；只移绿点，格子不动，不跳路由 |
| 底栏「放大观测」 | 进播放页，同一引擎 |
| 激活另一格 | 上一格静音保留，不关闭 |
| 去首页点另一间房 | 旧的那间若在盒里 → 静音保留；不在盒里 → 关闭 |
| 移出一格 | 关掉这一格；若是焦点，焦点清空 |
| 取消观测发声 | 焦点清空，画面留在墙上静音播 |

### 离开墙再回来

| 操作 | 该有的现象 |
|---|---|
| 开了「离开后继续播放」 | 回来直接出画，不转圈 |
| 没开（默认） | 会话已回收，回来按格重连；地址没过期就跳过平台往返 |

### 岛

| 操作 | 该有的现象 |
|---|---|
| 在墙上点岛 | 放大当前焦点（进播放页） |
| 在别的页面点岛，房间**在盒里** | 回**墙** |
| 在别的页面点岛，房间不在盒里 | 回播放页 |
| 墙上点"取消观测发声" | 焦点清空，岛回时钟 |

## 历史缺陷与它们的根因

这四条不是手感问题，是模型缺位的症状。每条都已经写成测试，在修复前跑红。

| # | 现象 | 根因 |
|---|---|---|
| 1 | 声音在响，但没有一格有绿点，岛是头像圆 | `watchShow` 只认 `WatchActive`，不认 `a.media.roomKey`，于是给媒体层已经持有的房间**再开一个会话** |
| 2 | 从墙放大进去再按 X，回到墙上这格黑了 | `closeMedia` 把"结束声音焦点"和"结束这一路"当成同一件事 |
| 3 | 墙上换一间看，上一间就没了 | `watchDropActive` 直接 `watchCloseSession`，没问这一间还在不在盒里 |
| 4 | 离开墙几秒回来，整面墙重新 buffering | `watchHide` 把"看不见"和"关掉"焊在一起 |

## 过渡：三处"没有动画"是三件事

| 哪一处 | 性质 | 结论 |
|---|---|---|
| 顶栏 tab / 分区之间 | 2026-11-14 `d488013` 关掉路由转场。方向模型与平级路由不匹配，判断正确 | **保持不动**；但当时是全局开关，顺带关掉了播放页那条路 |
| 卡片网格的进出场 | 2026-11-21 `66a4aae` + [0010](../decisions/0010-switch-content-still.md)。在用户正在读的内容上施加位移，被读成"画面在抖" | **永不恢复**，`TestContentLayerHasNoMotion` 继续守着 |
| 格子 → 播放页的连续放大 | 2026-11-23 落地（`Match` / `Fly`）。只在该过渡窗口内挂，见下 | **已做**；反向收缩撤掉，见下 |

前两件的结论不能互相牵连：**在内容上动**和**在表面之间换位置**是两件事。

### 过渡契约

| 过渡 | 动效 | 预算 | 状态 |
|---|---|---|---|
| 墙格 → 播放页 | 同一元素连续放大，起飞瞬间呈现尺寸即为全尺寸 | 280ms `Snappy` | **已落地** |
| 播放页 → 墙 | 硬切 | — | **有意为之**，见下 |
| 播放页 → 后台收听 | 舞台收进岛的头像 | 280ms `Snappy` | 未做：需要岛也参与 Match，当前岛不是共享元素 |
| 列表卡片 → 播放页 | 封面长成舞台，落地后流淡入 | 300ms | 未做：舞台身份已就位，卡片封面还没有 |
| 墙内加 / 移一格 | 其余格子弹簧位移（布局重排，不是 `Match`） | 190ms | 先过 0010 三道门槛 |
| 墙内激活 | 不动 | — | — |
| 顶栏 tab / 分区 | 不动 | — | 0010 |
| 窗口最大化 / 还原 | 不动 | — | MyGo 自己的契约：resize 不 animate |

`Router.Transition` 是路由器级字段，不能按次设。所以封装在 `surface_motion.go`
的一处：`pushRoute` 在"目标或来源是播放页、且焦点非空"时临时切到
`TransitionMatch`，`tickRouteTransition` 在 `Shell` 每帧检查截止时刻恢复
`TransitionNone`。恢复晚 120ms——Router 自己的淡出还在收尾，提前切回会把
旧页面直接抽走，看起来是闪一下。

**`Match` 只在过渡窗口内挂。** 格子与舞台身上的 `Transition{Match, Fly}` 都要
判 `routeTransitionUntil` 非零。常挂着等于告诉 MyGo「这个元素的尺寸变化也要
动画」，于是最大化/还原时整墙一起弹十几帧、视频每帧重新适配——2026-11-23
报的「最大化会闪」就是它。文档里 resize 本来就不该 animate。

**退出是硬切，这是设计，不是欠账。** 一个 `ui.VideoPlayer` 只能被一个
`ui.Video` 画出来（两个元素只有一个出画），而退出时画面必须已经交回墙上的
格子——播放舞台这一侧就没有引擎可画。`TransitionMatch` 会在淡出期间重建旧
页面，那一帧舞台的 player 是 nil，整块闪成封面或黑底（帧探针实测第 0–2 帧
全黑，之后才淡入）。硬切则新墙第一帧就带着同一路画面，没有空窗。回归是
`TestExitToWallKeepsThePicture`。

所以 `exitPlayer` 只做三件事：把路由器切回 `TransitionNone`（进场后 400ms
内就退出时它可能还停在 Match）、`closeMedia()`、`Router.Back()`。没有
`exitMatchKey`、没有 `playerFrom`——那些是为收缩过渡准备的，收缩没了就一起
删掉。

**飞行元素必须自己带外形。** MyGo 把带 `Match` 的元素画在祖先的裁剪之外
（`transitions.md`：「paints out of the clips of the scroll views and
containers around it」）。所以圆角、描边这类只由祖先 `Clip()` 提供的外形，
飞行途中会整段消失——2026-11-23 报的「过渡动画时是直角」就是这个：外壳的
`Radius(16).Clip()` 在飞行帧失效，舞台自己只有黑底。修法是把同样的圆角挂到
飞行元素本身（`player.go` 的 stage）；它跟着 look 一起插值，全程一致。

这条是通则，不是这一处：**任何会被 `Match` 飞的元素，外形都要画在自己身上。**

不用定时器收尾：窗口最小化时定时器还会跑，而那时根本没有帧要画。

**不许散到调用点**——散着就是下一个"四套机制并存"。
