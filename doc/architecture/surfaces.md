# 四个表面：单直播间 / 后台收听 / 悲鸣观测 / 灵动岛

日期：2026-11-22。
取舍与复查条件见 [0012](../decisions/0012-surface-model.md)，
观测墙本身的规则见 [watch.md](watch.md)，播放链路见 [playback.md](playback.md)。

## 一句话

产品里只有两个问题：**声音在谁身上**，**画面出现在哪**。其余都是这两件事的呈现。

四个"场景"不是四套播放器，是**一个会话集合的三个视图加一个指示器**：

| 表面 | 它是会话的什么 |
|---|---|
| 悲鸣观测 | 墙上每个会话的格子视图（可多路同时可见） |
| 单直播间 | 焦点会话的全尺寸视图 |
| 后台收听 | 焦点会话**没有任何全尺寸视图**时的状态，不是一种模式 |
| 灵动岛 | 焦点会话的指示器，形态只看焦点在不在；当前表面只决定 X 的文案与动作 |

所以 `background` 不该是一个字段，它是 `presentation(focus) == Hidden` 的推论。
同理"墙上 active"不是第二种播放，就是焦点会话被画在格子里。

## 三个正交轴

```text
S   会话集合     每间房至多一个会话（引擎 / 流 / 音量 / 播放态 / 弹幕）
F   声音焦点     标量，至多一个，或空
R   路由与分区   home / follows(streamers|subs|watch) / player
```

三个派生量，各只有一个求值点：

| 派生量 | 求值 | 现在的实现 |
|---|---|---|
| 焦点 `F` | `a.focus *roomSession` | 唯一写者 `setFocus`（`surface_motion.go`） |
| 呈现尺寸 `P(s)` | `presentSizeForSession()` | 唯一入口，`fullSize()` 判全尺寸 |
| 墙上 active | `wallActiveKey()` | 焦点在墙上的推论，不再存字段 |
| 后台收听 | `inBackground()` | `fullSize()` 的反面，不再存字段 |
| 岛形态 | `islandFormOf()` | 两种：时钟 / 有焦点（`focusAlive` 判活） |

## 组合表

| 路由 \ 焦点 | F=∅ | F=k，k 在墙上 | F=k，k 不在墙上 |
|---|---|---|---|
| home / follows 其他分区 | 岛=时钟 | 岛=主播条；k 隐藏解码 160×90 | 同左 |
| follows/watch | 岛=时钟；全格静音预览 | 岛=主播条；k 格 active + 绿点 | 墙照常；k 隐藏出声；岛=主播条 |
| player（目标是 k） | — | 岛=展开；全尺寸 + 弹幕 | 同左 |

第三列是过去没有定义的一格，也是三个洞的来源（见下）。

## 七条不变量

凡是"X 必须 Y"都写成可执行的测试，不写在文档里当口号。

1. **至多一路出声。** 任意时刻，非 0 音量的播放器不超过一个。
2. **出声必有播放器。** `F != ""` 时，该会话的播放器非 nil 且未关闭。
3. **一个房间至多一个引擎。** 同一 `platform|roomID` 同时最多一个 `*ui.VideoPlayer`。
4. **呈现尺寸与表面一致。** 全尺寸视图 → 0,0；格子视图 → 格子物理像素；无视图 → 160×90。
5. **岛形态与焦点一致。** 焦点活着（引擎在、正在取流，或正在看播放页）时岛上必有
   那一间；焦点结束（`setFocus(nil)`）时岛回时钟。
6. **进播放页不停，离开墙才停。** 从墙上点进某一间，墙上的其余格子继续播
   （只跳过渲染）；去首页 / 别的分区才算离开墙，非焦点会话停掉，回墙重建。
   没有「离开多久就回收」的窗口，也没有开关（2026-11-25）。
7. **弹幕只属于全尺寸视图。** 离开播放页即断开并清空。

## 四条操作路径与它们该有的现象

### 进 / 出播放页

| 操作 | 该有的现象 |
|---|---|
| 列表点卡片 | 卡片封面长成舞台，落地后流淡入；弹幕新连一条 |
| 墙上双击 / 点岛 | 同一元素从格子矩形连续放大到舞台；画面第一帧起就是全尺寸；不重取流 |
| 点 X，房间**在墙上** | 声音收掉，退回墙，这一格**还亮着**变静音预览 |
| 点 X，房间**不在墙上** | 彻底关闭，回上一页 |
| 在播放页按 Esc | 第一档是收起：退回打开它之前那一页，焦点和声音都留着 |
| 顶栏 tab 离开 | 后台收听：声音不断，岛不动，还是那一条主播信息 |

### 墙上

| 操作 | 该有的现象 |
|---|---|
| 单击格子 | 激活：焦点移过去，声音切过来，留在墙上 |
| 双击格子 | 进播放页，同一引擎 |
| hover 底栏「在墙上听」 | 和单击同义：焦点移过去，不跳路由 |
| 底栏「放大观测」 | 进播放页，同一引擎 |
| 激活另一格 | 上一格静音保留，不关闭 |
| 去首页点另一间房 | 离开墙即停掉非焦点会话；旧的那间作为上一焦点也会被关闭 |
| 移出一格 | 关掉这一格；若是焦点，焦点清空 |
| 取消观测发声 | 焦点清空，画面留在墙上静音播 |

### 离开墙再回来

离开墙（去首页 / 关注主播 / 订阅分区）时 `watchPark` 停掉非焦点会话，签名地址
留在 `wall.resume`。回到墙上 `watchShow` 缺谁补谁：地址没过期就跳过平台往返，
直接 `loadfile`；过期了重新取流。没有开关，也没有「离开多久才回收」的窗口。
进播放页不算离开墙。

### 岛

| 操作 | 该有的现象 |
|---|---|
| 在墙上点岛 | 放大当前焦点（进播放页） |
| 在别的页面点岛 | 回这一间的**播放页**（不管它在不在墙里；热区写的是「回到直播间」） |
| 在播放页点岛 | 收起（和 Esc 第一档一致） |
| 在播放页按 Esc | 收起这一路：退回打开它之前那一页。目标页上还有它的画面：墙格飞回那一格、卡片缩回那张卡；都没有就缩进岛，声音留着 |
| 收起之后再按 Esc | 结束这一路：收声，岛回时钟 |
| 点岛上的 X（任何页面） | 结束这一路：在墙上只收声、留静音格；不在墙上连会话一起关。在播放页上退回上一页 |
| 墙上点"取消观测发声" | 焦点清空，岛回时钟 |

## 历史缺陷与它们的根因

这六条不是手感问题，是模型缺位的症状。每条都已经写成测试，在修复前跑红。

| # | 现象 | 根因 |
|---|---|---|
| 1 | 声音在响，但没有一格有绿点，岛是头像圆 | `watchShow` 只认 `WatchActive`，不认 `a.media.roomKey`，于是给媒体层已经持有的房间**再开一个会话** |
| 2 | 从墙放大进去再按 X，回到墙上这格黑了 | `closeMedia` 把"结束声音焦点"和"结束这一路"当成同一件事 |
| 3 | 墙上换一间看，上一间就没了 | `watchDropActive` 直接 `watchCloseSession`，没问这一间还在不在墙里 |
| 4 | 离开墙几秒回来，整面墙重新 buffering | `watchHide` 把"看不见"和"关掉"焊在一起 |
| 5 | 收起的直播间（从列表打开）点岛上的 X 没反应，Esc 却能关 | `watchDeactivate` 第一行 `if WatchActive == "" { return }`，而从列表打开的焦点从来没写过 `WatchActive` |
| 6 | 从首页打开一个**墙内**房间，收起时按"回墙"处理，落回首页那一侧没有可接的元素 | 判据用「房间在不在墙」/「关注页上次停在观测墙」代理，而不是「这次从哪一页进播放页」 |

## 过渡：三处"没有动画"是三件事

| 哪一处 | 性质 | 结论 |
|---|---|---|
| 顶栏 tab / 分区之间 | 2026-11-14 `d488013` 关掉路由转场。方向模型与平级路由不匹配，判断正确 | **保持不动**；但当时是全局开关，顺带关掉了播放页那条路 |
| 卡片网格的进出场 | 2026-11-21 `66a4aae` + [0010](../decisions/0010-switch-content-still.md)。在用户正在读的内容上施加位移，被读成"画面在抖" | **永不恢复**，`TestContentLayerHasNoMotion` 继续守着 |
| 格子 → 播放页的连续放大 | 2026-11-23 落地（`Match` / `Fly`）。身份常挂，只有刚 resize 的几百毫秒例外，见下 | **已做**；反向收缩同样在（见下） |

前两件的结论不能互相牵连：**在内容上动**和**在表面之间换位置**是两件事。

### 过渡契约

过渡只由一件事决定：**这一间的画面在两个表面之间怎么走**（`picture`，见
`surface.go`）。不看「从哪一页点进来」——那是一次性的代理，换个台就过期。
操作路径只决定两件别的事：焦点留不留（收起 / 结束）、路由去哪（Back / Push）。

**画面归属**（`pictureOn(key, 目标页, 分区, 焦点活不活)`），按优先级：

| 归属 | 什么时候 | 画的是什么 |
|---|---|---|
| 播放页 | 目标路由是播放页、焦点是它 | 全尺寸画面 |
| 墙格 | 目标页是观测墙、它在墙上 | 同一个播放器 |
| 卡片 | 目标页的网格里还看得见它的卡片 | 封面 |
| 岛 | 收起后它还出声（引擎在 / 正在取流），且不是全屏 | 不是画面，是声音的家 |
| 没有 | 结束、全屏、或者目标页上没有它的画面 | — |

两端归属的组合决定过渡，只有这几种：

| 源 → 目标 | 动效 | 预算 |
|---|---|---|
| 墙格 ↔ 播放页 | 同一个播放器连续放大 / 收回（`Match` + `Fly`） | 280ms `Snappy` |
| 卡片 → 播放页 | 恒飞（同一操作永远同一结果）；像素：有活画面画活画面，没有画封面 | 280ms |
| 播放页 → 卡片 | 画面从舞台缩回那张卡片 | 280ms |
| 播放页 → 岛 | 画面从舞台缩进岛 | 280ms |
| 岛 → 播放页 | 同上（恒飞，像素按有没有活画面选） | 280ms |
| 其余（没有画面可接） | 硬切 | — |
| 顶栏 tab / 分区、墙内激活 | 不动 | 0010 |
| 墙内加 / 移一格 | 其余格子弹簧位移（布局重排，不是 `Match`） | `ui.Snappy`，无固定时长 |
| 窗口最大化 / 还原 | 不动 | MyGo 自己的契约：resize 不 animate |

**同一枚画面，只是像素来源不同。** 飞不飞只由「两端有没有几何」决定；这一间
此刻有没有在出图，只决定飞行块里画什么：有活画面画活画面，没有才画封面
（`planTransition` 的 `pixels`）。2026-11-25 那次报障（「点岛放大直播间，过程中
显示封面然后变成直播画面」）的根因是**飞的是封面**，不是"飞"——同一个操作。
2026-11-26 之前按"有没有引擎"分叉成"飞 / 硬切"，于是同一张卡片收起后再打开
就没了动画；这条分叉已删掉，`TestReopenSameCardAnimatesAgain` 守着它。

**点岛的起点是岛。** 同一页上即便有这一间的卡片，点岛也不从卡片起飞——用户点的
是屏幕正中的岛，画面却从列表里某张卡片长出来，读起来就是「不知道从哪冒出来一块
封面」。墙格仍然优先：在观测墙上，这一间的画面确实在那一格里。

**收起的第一帧必须等于舞台最后一帧。** 飞行块的底图、模糊、压暗、底色都从
`backdropLayers` 一处出，和舞台同一套；起飞那一帧黑边区不能从「糊」跳到「实」。
`TestLeaveFlightStartsAsTheStage` 逐像素比黑边区。

**进播放页的同一拍就要把呈现尺寸推成全尺寸。** 硬切没有 280ms 的封面飞行挡着，
后台那一路还在 160×90 上渲染：晚一帧推，第一帧就是一张放大的小图。`enterPlayer`
在 `Push` 之后立刻 `applyPresent()`，早一个帧间隔让渲染线程交出全尺寸那一帧。

**操作路径 → 归属 → 路由**，一张表：

| 操作 | 焦点 | 路由 | 起点 / 落点 |
|---|---|---|---|
| 首页 / 订阅卡片点击 | 换成它 | Push 播放页 | 卡片 → 播放页 |
| 关注主播行点击 | 换成它 | Push 播放页 | 卡片 → 播放页（行也是 grid 铺的，有卡片矩形） |
| 搜索命中 / 房间号 | 换成它 | Push 播放页 | 当前页有它的卡 → 卡片；否则硬切 |
| 墙格单击 | 换成它 | 不动 | 不动（只换绿点和岛） |
| 墙格双击 / 底栏放大 | 换成它 | Push 播放页 | 墙格 → 播放页 |
| 非播放页点岛 | 仍是它 | Push 播放页 | 墙格 > 岛（不认卡片） |
| 播放页点岛 / Esc | 留着 | Back 到来时那一页 | 目标页上：墙格 > 卡片 > 岛 > 硬切 |
| 播放页点顶栏 tab / 切平台 | 留着 | Push 目标页 | 同上（目标页的归属） |
| 播放页里搜索换台 | 换成新的 | Replace 播放页 | 同页换内容，不动 |
| 岛上的 X / 全屏返回钮 | 清空 | Back 到来时那一页 | 墙格 > 硬切（卡片和岛都不再代表它） |

**`Router.Transition` 只在两种情况下是 `TransitionMatch`**：墙格 ↔ 播放页
（`Match` 需要路由器同时渲染两页）。其余一律 `TransitionNone`——路由立刻
切走，目标页从第一帧起就是清楚的，只有一块画面在飞（`surface_flight.go`）。
截止时刻由 `tickRouteTransition` 收，用**视图时钟**（`App.frameNow`），
和 Router 的进度同一个时基。

**为什么不做整页交叉淡化。** 播放页是一整块不透明的画面，列表是浅色内容，
两页同时按透明度混，中间那几帧就是一层灰雾：视频从卡片后面透出来，控制条
的深色长条浮在卡片上（2026-11-24 报的「非墙直播间点岛收起很难看」）。
Router 自己的注释也写了同一件事（Across 只让新页淡入，两页混在一起会糊）。

**`Match` 常挂，但窗口刚改过尺寸的那几百毫秒不挂。** 墙格和舞台身上都必须
有身份，否则点击那一帧没有起点可飞（点击发生在页面构建之后）。带 `Match`
的元素在 resize 时会做尺寸动画（「最大化会闪」），所以 `Shell` 每帧记一次
窗口尺寸，`matchable()` 在改尺寸后的 400ms 内返回假。

**飞回墙格要两拍。** 舞台的身份可能正好落在 resize 那 400ms 里（没挂上），
所以离开时先补一拍：这一帧让舞台带上身份，两帧后再换路由（`exitArm`）。
其余落点都是我们自己画的飞行，不需要两拍。墙格那一侧也被同一个
`matchable()` 挡着，所以**过渡窗口本身（`routeTransitionUntil` 非零）也放行
两侧的 Match**——resize 后的 400ms 内退出同样能飞回格子。

**收起不做整页交叉淡化，也不凭空造画面。** 卡片、岛都是这一间实际存在的
表面；目标页上没有它的画面时硬切，不在内容层上补一层淡入淡出。

**演完之前不换呈现尺寸。** 离开播放页时 `playerExitUntil` 记一个截止时刻，
`fullSize()` 在这段时间里仍然为真；`tickSurface` 到点才切到后台（160×90）
或墙格尺寸。提前收尺寸，飞出去的舞台会在半路变糊。

**焦点清空之后舞台还要有身份。** 关闭时 `setFocus(nil)` 立刻收声，但飞回
格子的起点是上一帧的舞台；这几百毫秒由 `exitMatchKey` 顶着
（`stageMatchKey` 优先读焦点，焦点空了读它）。`exitMatchKey` 必须保留到
`tickRouteTransition` 的 `playerExitUntil` 到点才清——提前清，转场帧的舞台
会丢掉身份，Router 就把整块播放页按透明度淡出叠在墙上（2026-11-24 修）。

**墙内房间关闭只收声，不关引擎。** 引擎留在同一个 `roomSession` 里，
墙格画的就是它——不需要延迟放手，也不需要先把引擎交给谁。墙外的房间
关闭时才 `closeSession`，那条路没有画面可接，硬切。

**唯一求值点。** 过渡的种类只由 `surface_plan.go` 的 `planTransition(from, to,
fromOK, toOK, live)` 给出，四条规则：同一枚画面（墙格 ↔ 播放页）→ `Match`；
两端都有几何 → `Fly`（像素按 `live` 选活画面 / 封面）；任一端没有几何 → `Cut`
且带 `reason`；两端同一表面 → `Cut`。`enterPlayer` / `leavePlayerTo` /
`pushPage` / `closeFocus` 只负责组装输入和换路由，**不许自己再判一次**。
「结束这一路」（X / 退出直播间）不进 `Fly`：它没有要去的地方（墙格除外，那格
本来就在继续画同一枚画面）——明确关掉一个直播间，不需要收尾动画。

**唯一的时长。** 表面之间的过渡只有一个预算（`theme.MotionSurface` = 280ms，
`surfaceFlightDur` 与 `routeTransitionDur` 都是它），收尾余量是
`theme.MotionSlack`。控件自己的反馈分五档（`MotionMicro` / `MotionChrome` /
`MotionToggle` / `MotionReveal` / `MotionSurface`，见
`internal/theme/motion.go`），**不许再各自发明第六档**；`make gate` 的
**motion** 检查盯着这件事。

**悬停反馈和选中反馈用同一种语言。** 同一枚控件上，底色、描边和文字色必须走同一
族动效（`theme.HoverInk()` 弹簧）——底色瞬间跳、文字在弹，读起来是两种反馈，
用户分不清哪一下代表"选中了"。写法只有两个：`internal/ui/hover.go` 的
`hoverSurface`（铺底）与 `hoverInk`（着色/描边）。**`internal/ui` 里不许再有
`if x.Hovered() { x.Background(...) }`**——那是瞬间跳的来源，也是"同一屏几种
节奏"的来源。滑块负责"你点了哪一格"，底色负责"指针在哪"，两者都不写模型。

**不许散到调用点**——散着就是下一个"四套机制并存"。
