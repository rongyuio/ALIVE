# 悲鸣观测（观测墙）

日期：2026-11-21。状态：已落地。取舍见 [0011](../decisions/0011-watch-wall.md)，
平台并发实测见 [measurements](../reference/measurements.md) 的「观测墙并发」。

## 它是什么

关注页的第三个一级分区。观测盒里最多 12 间，同屏显示实时画面；每一格都是一个
**无弹幕的单直播间缩小版**：全档取流、真实音频输出、默认静音、按格子物理像素
呈现。

- 单击格子：放大成播放页，**同一个引擎接管**，不重新取流。和首页卡片、
  关注行、搜索结果同一个语义——全应用里"点一张直播画面"只有这一种结果。
- 想在墙上听某一间而不进去：hover 底栏那颗「在墙上听」。声音切过去，上一间
  只静音、不重开、不跳路由。这是墙上唯一不跳路由的入口。
- 点灵动岛：回播放页（或回墙，见 `surfaces.md`）。
- **没有双击**。全应用只有墙格用过双击，2026-11-23 删掉。
- 墙上不显示弹幕，也不保留弹幕连接；只有放大成播放页时才连一条全新的。
- 墙头没有常驻状态；正在播放谁由灵动岛承担。墙上岛展开显示当前房间。
- 墙头的「＋」展开添加面板：一行说明「从关注里挑，点一下收进观测盒」+ 候选
  chip（`＋ [品牌色平台] 名字`）；点 chip 收进观测盒，面板收起。
- 最多 12 间，不是按带宽算的；用户带宽不在产品判断里。
- 墙格可以拖动换位，顺序落盘。active 跟着房间身份走，换位不会把声音切到别的格子。

## 分层

```text
internal/ui/follows_page.go     第三个一级分区、分区顺序
internal/ui/watch.go            墙面：布局、格子、控件、添加面板
internal/ui/watch_media.go      wallMedia / wallSession：每格取流、静音、重连
internal/watch/layout.go        纯布局：1–12 间、16:9、铺满不裁剪
internal/ui/player_media.go     active 在播放页时的所有权、弹幕生命周期
internal/playback              libmpv 薄壳；呈现尺寸、起播静音、跳过音频门
```

墙和播放页不是两套播放器。`wallSession` 和 `playerMedia` 是同一路引擎在不同
位置的两种所有权。

## 所有权与交接

`a.WatchActive` 是当前出声那间的 `platform|roomID`。**一激活就接管进
`playerMedia`**；`wallSession` 只保留还没出首帧的 pending 格和所有非 active 格。

| 归属 | 什么时候 | 画面 | 声音 | 谁驱动 |
|---|---|---|---|---|
| `wallSession` | 非 active 预览；active 还没出首帧 | 格子物理像素 | 无 | `watchTick` |
| `playerMedia` | 激活完成；从播放页退回墙 | 格子物理像素 | 开 | `mediaTick` |

### 呈现尺寸只有一个旋钮

「这一路该画多大」由 `playerMedia.presentSizeFor()` 一处求值，`applyPresent()`
推给引擎（`videoTrack.SetPresentSize`，0 表示视频原始尺寸）：

| 位置 | 呈现尺寸 |
|---|---|
| 播放页（且不在后台） | 0,0 —— 视频原始尺寸 |
| 观测墙上的 active | 格子物理像素（2× DIP，上限 1280×720） |
| 其它页面的后台收听 | 160×90 |

以前这里有**四套并行机制**在管同一件事：`Options.MaxWidth/MaxHeight` 开流时
收格子、`SetPresenting(bool)` 表示全尺寸/160×90、`lastW/lastH` 给墙上重开
继承、各个调用点各自补一次 `SetPresentSize`。每条路径只记得自己那一套，
于是「墙 → 播放页」永远停在格子分辨率——整屏都是放大的糊图。

现在上限（`Options.MaxWidth/MaxHeight`）**只做安全阀**，不参与选尺寸；
`presentSizeFor` 是唯一的判断，`applyPresent` 是唯一的推送入口。换引擎时
用 `applyPresentForce`（新引擎上的尺寸是它自己的默认值，和意图相等不代表
推过）；其余时候值没变就不推——`SetPresentSize` 每次都会让引擎立刻重渲染一帧。

`third_party/mygo/plugins/video` 里还有一条必须守住的：`target()` 不能把
裁剪后的尺寸写回 `p.width/p.height`。那是 mpv 报的原始尺寸，写回之后上限
就成了单向阀——收得紧、放不回。

交接规则：

- **墙上激活 / 退出 active**：只换所有权、声音焦点和强调环；呈现尺寸不变
  （墙上两种状态都是格子）。
- **墙 → 播放页**：`watchAdoptActive(false)` 把 `player` / `stream` / `upstream`
  原样交给 `playerMedia`，`applyPresent()` 放回全尺寸；弹幕由 `ensureDanmaku`
  重新连一条。取流、首帧、地址都不重来。
- **从墙上点岛进播放页**：引擎本来就在 `a.media` 里，`watchAdoptActive` 直接
  返回 false，走的是 `attachMedia`——它也必须调 `applyPresent()`，这条漏过一次。
- **播放页 → 墙**：`detachMedia` 保留引擎，`applyPresent()` 把尺寸收回格子；
  墙直接画 `a.media.player`，视频在卡片里 `Contain`。弹幕在离开时断开并清空。
- **墙上 active 的刷新 / 热切换**：新引擎接上时 `applyPresentForce()`，仍按
  当前位置求尺寸，不缩回 160×90。
- **在墙上激活另一格**：`watchReleaseActive` 把 `playerMedia` 持有的这一路移回
  `wallSession`，静音但不停播；再接管新的一格。旧格子的 `player.Close()` 归墙
  管理，不再由取流 ctx 管。
- **引擎不挂取流 ctx**：`playback.Open` 用 `context.Background()`，生命周期归
  `*ui.VideoPlayer`。否则墙上的画面会在切房 / 换档时被顺手关掉。

墙不可见（播放页、首页）时，`watchHide` 只标记不可见，**不关会话**——这是
"暂离"语义的全部：看不见只意味着不渲染，不意味着离开。回来时 `watchShow`
重新计时并按布局补齐，不会重取流。

**看不见时不再渲染。** 插件的渲染门控按"最近有没有人取帧"判断：300ms 内没人
取帧就跳过 `native.render()`，回来第一次取帧强制渲一帧（实测 47–53ms 出新帧）。
这不影响解码和连接，省的是每帧的 YUV→RGB 与回读——12 格各按格子尺寸转一遍，
一秒几百 MB，却没有任何地方会看到它。

**省流量是可选项，不是默认。** 墙头那颗「暂离时省流量」默认关：关＝保留流，
回来无缝；开＝离开 2 秒后关掉非焦点会话，回来重新取流。这笔账里唯一要用户
决定的是带宽，因为解码在硬解下本来就便宜（见
[measurements](../reference/measurements.md)「暂离时到底花什么」）。

**解码也能挂起，不用改 mpv。** 渲染门控判定没人看之后，插件顺手设
`vd-lavc-skipframe=all`：解码器照常从 demuxer 取包但**不解帧**，所以连接、
缓存、音频时钟都照走；恢复时设回 `none`，解码器重建，实测 6–37ms 出新的
画面，之后按 1x 前进。

（不能用 `nonkey`：它会把 `vfps` 打零、缓存清零，管线停住。两者语义不同——
`all` 是"取包不解帧"，`nonkey` 在这条流上会让播放器直接停。）

挂起省的是 GPU 解码与每帧的显存→内存回读；硬解下单路 CPU 本来就只有
0.02–0.06 核，所以省下来的主要是 GPU 和内存带宽，不是 CPU。

**最小化也算看不见。** 最小化时 Shell 不重建，按路由判断的那条路走不到，
所以窗口的 `OnMinimize` / `OnRestore` 各挂一次 `WatchHidden` / `WatchShown`。
小窗把主窗口换下去时同理。

**离线格自己回来。** 蹲开播是墙的核心场景之一：`watchOffline` 落终态时排一次
退避重试，`watchTick` 到期就重新问平台。`failures` 不清零，一个长期没开播的
房间不该每两秒问一次。

## 生命周期

- 开格：`fetchStream` 取和播放页同一档位；`playback.Open` 全档、`StartSilent`、
  `SkipAudioGate`，呈现尺寸按格子物理像素（2× DIP，上限 1280×720）。
- `ended` / 长时间不推进：先 `RoomInfo`。平台说 `live=false` → 未开播态，停止
  重连；仍 live → 重取流。退避 2s / 8s / 30s / 120s。
- 签名地址到期：`Variant.Expires` 前重开这一路。斗鱼的 300 秒直链在墙上同样适用。
- 单格失败只重试自己；点击失败格就是重试，不需要额外按钮。
- 10 分钟混合 9 路浸泡里见过一次 `ended`，查 `RoomInfo` 是主播下播，不是并发上限。
  这条分流是必须的：下播后无限重连只会把一格永远卡在“连接结束”。

## 弹幕

弹幕只属于播放页。

- 墙里没有 `startDanmaku`、没有 `roomCtx`、没有 WebSocket。
- 离开播放页：`closeDanmaku`，清空 `DanmuLog` / 飞行弹幕 / 面板游标；再进来
  （从墙或从列表）都是全新连接，不保留上一段聊天。
- `ensureDanmaku` 每帧问一次；失败后退避 30 秒，避免平台拒绝时每帧重连。

## 布局

`internal/watch.Layout` 是纯函数，排的是**每格等大的网格**：枚举行数 1..n，
列数 = ceil(n/rows)，所有格同宽同高；每格画面按 16:9 contain，不裁剪。评分取
「所有格里最小的画面面积」最大，同分时空格更少、行数更多者优先；行按列左
对齐，最后一行不满时空位留在行尾右侧。

1440×800 下：2 间一行各约 700×394；3 间 2+1（C 在第二行左列，右下空），
每格约 700×394；5 间 3+2；7 间 3+3+1（右下两格空），每格约 460×259；9 间 3×3；
12 间 3 行 4 列。
**不会出现一大几小**，也不会为了塞满而裁剪。行数多了以后单格变小，这是等大网格的代价；换来的是每间房一样大、
视线不用在大小格之间跳。

墙上的格子**统一 16:9**，视频 `Contain`。不按每一路源比例排：

- 平台声明比例不可靠：同一批 B 站房间会给出 4:3，实际是 16:9；
- 读 `player.Size()` 更糟：那是渲染目标，而渲染目标又按格子比例设，会形成反馈，
  首帧到达后整面墙重排一次。

统一 16:9 是稳定的；竖屏/4:3 的流左右留黑，不裁剪。

墙面不画底色，落在页面的 `BgPrimary` 上；每一格是一个卡片：`RadiusMD` +
`BgSecondary` + 顶部 `TopLight`，和直播卡片同一套表面。格间用 `GridGap`（16），
不是自己写的 12。没有整块黑色矩形。

常态格子里只有画面；active 只加一圈强调色内阴影，不改格子大小——激活不该让
整面墙重排。hover 或键盘聚焦时，底部升起一条底栏，**底栏本身就是遮罩**，信息
和控件是一块：第一行是品牌色平台胶囊 + 主播名 + 标题，第二行直接复用播放页控制台：44 高玻璃条，左侧播放/刷新/音量（滑条+百分比），右侧放大/移出；弹幕/清晰度/线路/小窗/全屏都精简掉。每个 hover 的格子都显示完整控制条。active 的播放/暂停、刷新、音量分别直接调用
播放页的 `togglePlayback` / `retryStream` / `volumeControl`，没有墙专用分支；
非 active 格的播放/暂停切自己的 `player`，刷新只重载自己。**音量按格各存一份**
（`wall.volumes`，key 是 `platform|roomID`）：非 active 格显示自己记住的百分比和
静音图标，滑条填充用暗一档的 accent；点滑条 / 滚轮会先激活这一格再改它自己的
值——改的始终只是这格，别的格的值一动不动。active 格的音量仍走 `volumeControl`，
`setVolume` 负责把它记到当前 active 名下，切走再切回来还是那个值。每格音量随
`watchRooms` 一起落盘（`watchRecord.Volume`），重启后还是自己的；没调过的格不写，
重新上墙时继承当时的全局音量。加载态直接复用播放页整块遮罩、30px spinner 和 `正在拉取直播流…`，不再自己画小胶囊。不 hover 时不显示这些。

接通中 / 未开播 / 预览失败的提示不等 hover，常显在格子顶部中间；那是状态，
不是 chrome。

## 灵动岛

- 在观测墙上、且有 active 时：岛展开，显示当前房间标题、平台/房间号、头像；
  整块是回播放页的热区（进的始终是 active 那一间）。右侧收藏键自己收点击，
  收藏左边多一颗「取消观测发声」：取消 active、岛回到时钟，画面留在墙上做
  静音预览，不关引擎也不移出观测盒。
- 观测墙上没有 active 时：保持首页的时钟岛，不缩成圆。
- 其它页面后台收听：仍收成一枚头像圆。
- ~~岛上显示的是实际播放的档位；格子左上角也写 `平台 · 档位`~~——**代码里没有
  这两处**（2026-11-23 核对）。档位目前只在播放页控制条的下拉里可见；墙上和
  岛上都不显示。要么补实现，要么把这条期望删掉，不能留着当承诺。

## 落盘

`state.json` 的 `watchRooms` 只存房间身份和展示元数据：platform、roomID、name、
title、cover、avatar、hue、viewers。不存签名地址、不存会话状态、不存播放进度。
恢复时先出封面，不自动起播；最多 12 间，重复与空身份在读盘时清掉。

## 验证

- `internal/watch`：布局 1–12 间、16:9/竖屏/混合、边界、无重叠、上限。
- `internal/ui`：空态、两间大格、十二间上墙、单击进播放页、在墙上听不跳路由、
  每格音量独立且不抢焦点、12 间上限与去重、落盘、卡片右键入口、墙上岛展开与
  取消 active。
- 真实窗口（2026-11-21）：7 间同时出画；单击激活；岛展开；点岛进播放页日志
  `观测墙接管进播放页`，无加载层；退回墙日志 `detach`，同一引擎继续出声。
  截图在 `/d/tmp/watch-final.png` 等（临时文件，不入仓库）。
- 未跑：真实窗口下 10–12 路并发（产品上限 12；平台探针只测到 9 路）；4K 格子的
  CPU；平台限流时的真实退避曲线。
