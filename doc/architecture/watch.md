# 悲鸣观测（观测墙）

日期：2026-11-21。状态：已落地。取舍见 [0011](../decisions/0011-watch-wall.md)，
平台并发实测见 [measurements](../reference/measurements.md) 的「观测墙并发」。

## 它是什么

关注页的第三个一级分区。观测墙里最多 12 间，同屏显示实时画面；每一格都是一个
**无弹幕的单直播间缩小版**：全档取流、真实音频输出、默认静音、按格子物理像素
呈现。

- 单击格子：激活这一间——声音焦点切过去，绿点亮起，岛换成这一间，画面留在
  墙上。上一间只静音、不重开、不跳路由。hover 底栏的「在墙上听」是同一个动作。
- 双击格子：放大成播放页，**同一个引擎接管**，不重新取流。
- 键盘和读屏没有双击：Enter 与单击同义（激活），打开播放页走 hover 底栏的
  「放大观测」。双击是鼠标的快捷方式，不是唯一入口。
- 点灵动岛：在播放页上收起这一路，别的页面回这一间的播放页（见 `surfaces.md`）。
- 墙上不显示弹幕，也不保留弹幕连接；只有放大成播放页时才连一条全新的。
- 墙头没有常驻状态；正在播放谁由灵动岛承担。
- 收进墙没有墙上的入口：首页卡片右键、关注页行右键的「悲鸣观测」。收进去之后
  墙才出现这一格。
- 最多 12 间，不是按带宽算的；用户带宽不在产品判断里。
- 墙格可以拖动换位，顺序落盘。active 跟着房间身份走，换位不会把声音切到别的格子。

## 分层

```text
internal/ui/follows_page.go     第三个一级分区、分区顺序
internal/ui/watch.go            墙面：布局、格子、底栏控件
internal/ui/watch_media.go      wallMedia：会话表、每格取流、静音、重连
internal/watch/layout.go        纯布局：1–12 间、16:9、铺满不裁剪
internal/ui/player_media.go     active 在播放页时的所有权、弹幕生命周期
internal/playback              libmpv 薄壳；呈现尺寸、起播静音、跳过音频门
```

墙和播放页不是两套播放器。每一间房只有一个 `roomSession`，墙格和播放页画的
是同一个 `VideoPlayer`；`a.focus` 指向当前出声的那一间。

## 所有权与焦点

会话表的身份是 `platform|roomID`，每一间房一个 `roomSession`，住在
`a.watch.sessions`。`roomSession` 里同时有引擎、取流上下文、播放器、音量、
错误/离线态。

`a.focus` 是唯一的「谁在出声」。`setFocus` 是唯一的写入口，`wallActiveKey()` /
`focusPlaying()` / `presentSizeFor()` 都是它的推论。

| 状态 | 什么时候 | 画面 | 声音 | 谁驱动 |
|---|---|---|---|---|
| 非焦点会话 | 墙上预览 | 格子物理像素 | 无（`StartSilent`） | `watchTick` |
| 焦点会话 | 激活；从播放页退回墙 | 格子物理像素 | 开 | 媒体层心跳，内部也调 `watchTick` |
| 焦点会话 + 播放页 | 有全尺寸视图 | 0,0（原始尺寸） | 开 | 媒体层心跳 |

没有「搬移」：切焦点只换 `a.focus` 指向，引擎、流、连接一概不动。

### 呈现尺寸只有一个旋钮

「这一路该画多大」由 `a.presentSizeFor()` → `presentSizeForSession()` 一处求值，
`applyPresent()` 推给引擎（`SetPresentSize`，0 表示视频原始尺寸）：

| 位置 | 呈现尺寸 |
|---|---|
| 播放页（且不在后台） | 0,0 —— 视频原始尺寸 |
| 观测墙上的 active | 格子物理像素（2× DIP，上限 1280×720） |
| 其它页面的后台收听 | 160×90 |

以前这里有**四套并行机制**在管同一件事：`Options.MaxWidth/MaxHeight` 开流时
收格子、`SetPresenting(bool)` 表示全尺寸/160×90、`lastW/lastH` 给墙上重开
继承、各个调用点各自补一次 `SetPresentSize`。每条路径只记得自己那一套，
于是「墙 → 播放页」永远停在格子分辨率——整屏都是放大的糊图。

`Options.MaxWidth/MaxHeight` 现在没有生产调用点设置，字段留着但不参与选尺寸；
`presentSizeFor` 是唯一的判断，`applyPresent` 是唯一的推送入口。换引擎时
用 `applyPresentForce`（新引擎上的尺寸是它自己的默认值，和意图相等不代表
推过）；其余时候值没变就不推——`SetPresentSize` 每次都会让引擎立刻重渲染一帧。

`third_party/mygo/plugins/video` 里还有一条必须守住的：`target()` 不能把
裁剪后的尺寸写回 `p.width/p.height`。那是 mpv 报的原始尺寸，写回之后上限
就成了单向阀——收得紧、放不回。

交接规则：

- **墙上激活 / 换一格**：只换 `a.focus`。上一间若还在墙上，只收声、留静音预览；
  不在墙上就连引擎一起关。呈现尺寸跟着 `presentSizeForSession` 每帧重算。
- **墙 → 播放页**：`setFocus` 之后进播放页，`applyPresent()` 把尺寸放到全尺寸；
  弹幕由 `ensureDanmaku` 重新连一条。取流、首帧、地址都不重来。
- **播放页 → 墙**：焦点不动，`applyPresent()` 把尺寸收回格子；墙直接画
  `watchPlayer(key)` 返回的同一个播放器。弹幕在离开播放页时断开并清空。
- **焦点会话的刷新 / 热切换**：新引擎接上时 `applyPresentForce()`，仍按当前
  位置求尺寸，不缩回 160×90。
- **引擎不挂取流 ctx**：`playback.Open` 用 `context.Background()`，生命周期归
  `*ui.VideoPlayer`。否则墙上的画面会在切房 / 换档时被顺手关掉。

墙不可见（播放页、首页）时，`watchHide` 只标记不可见，**不关会话**——这是
"暂离"语义的全部：看不见只意味着不渲染，不意味着离开。回来时 `watchShow`
重新计时并按布局补齐，不会重取流。

**看不见时只跳过渲染。** 插件的渲染门控按"最近有没有人取帧"判断：300ms 内没人
取帧就跳过 `native.render()`；回来第一次取帧强制渲一帧并唤醒渲染线程，之后
按 mpv 的更新回调继续。实测 12 路同时恢复 125–141ms 出连续新画面，隐藏期间
12 路共 0.30 核（零拷贝）。省的是每帧的转换、上屏与回读，解码、连接、缓存、
音频时钟都不动。

**进播放页不停，离开墙才停。** 从墙上点进某一间，背后还是这面墙，退出就
回来：其余格子继续播，看不见只跳过渲染（上一段）。去首页 / 关注主播 /
订阅分区才是离开墙——非焦点会话在这里停掉：引擎关、签名地址留在
`wall.resume`，回墙时 `watchShow` 缺谁补谁，地址没过期就跳过平台往返。
焦点那一间不动：离开墙之后它就是后台收听。

没有开关（2026-11-25 去掉了「暂离时省流量」）：停不停只由「还在不在墙的
上下文里」决定。墙在用的时候保留解码的代价见
[measurements](../reference/measurements.md)「暂离与回到墙」。

**不要顺手挂起解码。** `vd-lavc-skipframe` 会把"回来"的延迟绑到关键帧间隔上：

| 隐藏 12 秒后的恢复 | 出新画面 | 隐藏期间（3 路） |
|---|---|---|
| `all` | 21.4 秒（= 等下一个关键帧） | 0.12 核 |
| `nonref` | 2.24 秒（解码器追赶缓存） | 0.13 核 |
| 不挂起 | **130–140ms** | 0.14 核 |

（2026-11-23，B 站 7734200，1080P 原画，零拷贝，12 路同时恢复 125–141ms、
0.30 核。）之前记的"挂起后 6–37ms 恢复"是探针手动把 skipframe 设回 `none`
量的，绕过了真实恢复路径，不作数——墙上因此冻过 8–22 秒。

同一次事故还修了一处状态写反：门控的 idle 标志在渲染线程里被写成"没在跳过"，
`Frame()` 于是一次都不唤醒、不强制重渲。解码挂着时 mpv 不再发更新回调，整格
冻住，直到 1.5 秒的停帧看门狗把整路重开——用户看到的就是几秒到二十秒的冻帧。
回归测试是 `plugins/video` 的 `TestFrameWakesAfterIdle` 与
`TestRenderGateDoesNotSuspendDecode`。

**最小化也算看不见。** 最小化时 Shell 不重建，按路由判断的那条路走不到，
所以窗口的 `OnMinimize` / `OnRestore` 各挂一次 `WatchHidden` / `WatchShown`。
小窗把主窗口换下去时同理。

**离线格自己回来，但探测是无感的。** 蹲开播是墙的核心场景之一，但格子上不能
因此反复闪「正在拉取直播流…」。`watchOffline` 落终态时排一次探测，到期后
`watchProbe` 只问一次 `RoomInfo`：

- 不动 `loading` / `err` / `offline`——格子一直是「主播暂时没有开播」，没有
  spinner、没有刷新提示。平台说开播了才走正常起播，那时才允许出现加载态。
- 退避 30s / 1m / 2m / 4m，加按房间号摊开的抖动，**上限 4m59s**：主播开播后
  墙上最多 5 分钟跟上。不要求实时。
- **不在墙上完全不探测**（路由离开观测墙、窗口最小化都算）。回到墙上时
  `watchShow` 把离线退避清零，立刻探一次。
- 首帧超时也先问平台：真下播就落未开播，此后按上面的节奏探测；仍 live 才按
  失败退避重开。`failures` 只在真的出了第一帧之后清零——引擎开出来不算，
  否则「平台说在播、实际不出帧」会 20 秒一轮永远循环。

## 生命周期

- 开格：`fetchStream` 取和播放页同一档位；`playback.Open` 全档、`StartSilent`、
  `SkipAudioGate`，呈现尺寸按格子物理像素（2× DIP，上限 1280×720）。
- 引擎按 `StartSilent` 起播（mpv 音量 0），而 `ui.NewEngineVideoPlayer` 把
  播放器记录的音量初始化成 1。挂上会话必须走 `roomSession.attachPlayer`：
  先把记录值对齐到 0，再让 `applySessionVolume` 推这一路真正的音量。少这一步，
  目标音量恰好是 100% 时写者会判成「已经推过」，引擎永远停在 0——播放页从
  分区卡片进入时没声音就是这么发生的（2026-11-24 修）。
- `ended` / 长时间不推进：先 `RoomInfo`。平台说 `live=false` → 未开播态，停止
  重连；仍 live → 重取流。退避 2s / 8s / 30s / 120s。
- 签名地址到期：`Variant.Expires` 前重开这一路。斗鱼的 300 秒直链在墙上同样适用。
- 单格失败只重试自己；点击失败格就是重试，不需要额外按钮。
- 10 分钟混合 9 路浸泡里见过一次 `ended`，查 `RoomInfo` 是主播下播，不是并发上限。
  这条分流是必须的：下播后无限重连只会把一格永远卡在“连接结束”。

## 弹幕

弹幕只属于播放页。

- 墙里没有 `startDanmaku`、没有 `roomCtx`、没有 WebSocket。
- 离开播放页：`closeDanmaku`，清空 `DanmuLog` / 飞行弹幕 / 面板游标；再进来
  （从墙或从列表）都是全新连接，不保留上一段聊天。
- `ensureDanmaku` 每帧问一次；失败后退避 30 秒，避免平台拒绝时每帧重连。

## 布局

`internal/watch.Layout` 是纯函数，排的是**每格等大的网格**：枚举行数 1..n，
列数 = ceil(n/rows)，所有格同宽同高；每格画面按 16:9 contain，不裁剪。评分取
「所有格里最小的画面面积」最大，同分时空格更少、行数更多者优先；行按列左
对齐，最后一行不满时空位留在行尾右侧。

1440×800 下：2 间一行各约 700×394；3 间 2+1（C 在第二行左列，右下空），
每格约 700×394；5 间 3+2；7 间 3+3+1（右下两格空），每格约 460×259；9 间 3×3；
12 间 3 行 4 列。
**不会出现一大几小**，也不会为了塞满而裁剪。行数多了以后单格变小，这是等大网格的代价；换来的是每间房一样大、
视线不用在大小格之间跳。

墙上的格子**统一 16:9**，视频 `Contain`。不按每一路源比例排：

- 平台声明比例不可靠：同一批 B 站房间会给出 4:3，实际是 16:9；
- 读 `player.Size()` 更糟：那是渲染目标，而渲染目标又按格子比例设，会形成反馈，
  首帧到达后整面墙重排一次。

统一 16:9 是稳定的；竖屏/4:3 的流左右留黑，不裁剪。

墙面不画底色，落在页面的 `BgPrimary` 上；每一格是一个卡片：`RadiusMD` +
`BgSecondary` + 顶部 `TopLight`，和直播卡片同一套表面。格间用 `GridGap`（16），
不是自己写的 12。没有整块黑色矩形。

常态格子里只有画面；active 只加左上角一颗脉冲绿点，不改格子大小——激活不该让
整面墙重排。hover 或键盘聚焦时，底部升起一条底栏，**底栏本身就是遮罩**，信息
和控件是一块：第一行是品牌色平台胶囊 + 主播名 + 标题，第二行是播放页控制台的
精简版，按格宽分三档——格宽 ≥520 时沿用播放页的 44 高，300–519 收到 34 高，
再窄让出音量百分比。左侧播放/刷新/音量（滑条+百分比），右侧放大/移出；弹幕/
清晰度/线路/小窗/全屏都精简掉。

active 格的播放/暂停走 `togglePlayback`；刷新走 `watchReload`，它按「是否焦点
且在全尺寸」分播放页整路重取和墙上重开两条路；音量走 `volumeControlFor`。
非 active 格的播放/暂停切自己的 `player`，音量走 `watchTileAudio`。

**音量按格各存一份**：会话在时住 `roomSession.volume`，会话不在时由
`wall.volumes` 冷存（key 是 `platform|roomID`）。非 active 格显示自己记住的
百分比和「在墙上听」键，滑条填充用暗一档的 accent；点滑条 / 滚轮只改这一格
记住的值，**不会激活这一格**。「在墙上听」是唯一一个只换声音、不进播放页的
入口。active 格的音量走 `volumeControlFor`，切走再切回来还是那个值。每格音量
随 `watchRooms` 一起落盘（`watchRecord.Volume`），重启后还是自己的；没调过的
格不写，重新上墙时继承当时的全局音量。

加载态直接复用播放页整块遮罩、30px spinner 和 `正在拉取直播流…`；未开播 /
失败 / 缓冲是格子顶部的小胶囊。不 hover 时只有状态提示，没有底栏。

## 灵动岛

- 在观测墙上、且有 active 时：岛展开，显示当前房间标题、平台/房间号、头像；
  整块是回播放页的热区（进的始终是 active 那一间）。右侧收藏键自己收点击，
  收藏左边多一颗「取消观测发声」：取消 active、岛回到时钟，画面留在墙上做
  静音预览，不关引擎也不移出观测墙。
- 没有焦点时：保持首页的时钟岛，不缩成圆。岛形态只看焦点在不在，不看当前
  在哪一页——焦点不在墙上时，岛显示的仍是那一条主播信息。
- 其它页面后台收听：还是同一条主播信息（不缩成圆），点它回到这一路，
  右边那颗 X 结束这一路。
- ~~岛上显示的是实际播放的档位；格子左上角也写 `平台 · 档位`~~——**代码里没有
  这两处**（2026-11-23 核对）。档位目前只在播放页控制条的下拉里可见；墙上和
  岛上都不显示。要么补实现，要么把这条期望删掉，不能留着当承诺。

## 落盘

`state.json` 的 `watchRooms` 只存房间身份、展示元数据和这一格自己的音量：
platform、roomID、name、title、category、sub、viewers、live、hue、cover、
avatar、volume。不存签名地址、不存会话状态、不存播放进度。
恢复时先出封面，不自动起播；最多 12 间，重复与空身份在读盘时清掉。

## 验证

- `internal/watch`：布局 1–12 间、16:9/竖屏/混合、边界、无重叠、上限。
- `internal/ui`：空态、两间大格、十二间上墙、单击激活、双击进播放页、在墙上听不跳路由、
  每格音量独立且不抢焦点、12 间上限与去重、落盘、卡片右键入口、墙上岛展开与
  取消 active。
- 真实窗口（2026-11-21）：7 间同时出画；单击激活；岛展开；点岛进播放页无加载层；
  退回墙同一引擎继续出声。当时日志行 `观测墙接管进播放页` / `detach` 已随事件
  体系换成 `wall.*` / `focus.change` / `present.change`。
  截图在 `/d/tmp/watch-final.png` 等（临时文件，不入仓库）。
- 未跑：真实窗口下 10–12 路并发（产品上限 12；平台探针只测到 9 路）；4K 格子的
  CPU；平台限流时的真实退避曲线。
