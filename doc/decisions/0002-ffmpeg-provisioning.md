# 0002 FFmpeg 随包分发与版本锁定

- **状态**：已决定，但**落地方式已废止**（2026-11-16）。播放走 libmpv（[0004](0004-libmpv.md)），
  它自带 FFmpeg；兜底路径（relay）也一并删除，我们不再分发任何 FFmpeg。本文保留作
  当时的推理与踩坑记录
- **日期**：2026-11-16
- **影响**：`internal/ffmpeg`、`third_party/ffmpeg`、`mygo.json`——三者都已在 2026-11-16 清空

## 背景

用户不应该关心自己装了哪些解码器。potplayer 安装时会提示装解码器/编码器包，
那是它的历史包袱；alive 不该复制这个包袱。

但播放离不开 FFmpeg：转封装、转码、自带解码、ffprobe 探测全依赖它。
一个"请先安装 FFmpeg 并加入 PATH"的提示，等于把问题丢给用户。

同时还有一个反向风险：机器上可能已经有各种版本的 FFmpeg（本机就有一份长期使用的），
如果我们用"找到哪个用哪个"，同一个 bug 在不同机器上表现不同，线上问题没法复现。

## 候选

### A. 要求用户安装

- 优点：零实现
- 代价：违背"解码能力由应用提供"；版本不可控；PATH 冲突

### B. 随包分发全量二进制

- 优点：版本绝对确定
- 代价：安装包体积增加约 200MB；每次发版都要重新打包

### C. 首次启动后台下载固定版本

- 优点：安装包小；版本仍然确定；可以和校验、原子替换一起做
- 代价：首次使用要等；需要处理下载失败、断点、校验

## 决策

**C，配合版本硬校验和原子落盘。**

- 固定 BtbN `autobuild-2026-11-02-12-51` 的 win64-gpl 静态包，二进制版本
  `n9.0.2-45-g1e65c6cd5d-20261102`，与本机长期使用的完全相同。
- 包 SHA-256 校验（`20e6537e…438116`）。
- 解出后放进 `%LOCALAPPDATA%\alive\bin`，原子替换，失败不留半份副本。
- 安装完成后再执行一次 `ffmpeg -version`，版本号不是
  `n9.0.2-45-g1e65c6cd5d-20261102` 就删除并报错——**换包不会静默生效**。
- 首次准备约 195MB 压缩包、解出约 200MB，本机实测 57 秒；之后启动不再下载。
- 播放需要组件但尚未就绪时，界面显示"正在准备播放组件"，装好后自动重试当前房间；
  这条路径按本轮启动预算等待，不把下载时间算成直播故障。
- `ALIVE_FFMPEG_DIR` 可指定唯一来源，供排障与测试使用；设置后不再回落到 PATH。
- PATH 只在开发机上作为兜底。

## 当时的两种来源（2026-11-16 补充，均已废止）

主路径改成 cgo 之后，FFmpeg 在仓库里以两种形态存在：`%LOCALAPPDATA%\alive\bin` 的
运行时下载副本（服务 relay 兜底），和 `third_party/ffmpeg` 的构建输入。两种都已随
`internal/relay`、`internal/ffmpeg` 的删除一并清空。

**2026-11-16 更新（最终结论）：** 播放主路径改用 libmpv（[0004](0004-libmpv.md)），
libmpv 自带 FFmpeg。随后 `internal/relay` 与 `internal/ffmpeg` 一起删除——兜底的真实
触发面只有「找不到 `libmpv-2.dll`」，那是安装损坏，兜底依赖的 ffmpeg 组件同样会缺。
**现在仓库里没有任何 FFmpeg 分发物**：`third_party/ffmpeg`（143MB 头文件与导入库）、
`internal/ffmpeg`（运行时下载）、`%LOCALAPPDATA%\alive\bin` 的缓存副本都不再需要。
本文下面的「首次启动下载」一节描述的实现已经不存在，保留作历史。

为什么主路径不放仓库外：DLL 是 exe 的加载期硬依赖（Windows 加载器在进程入口点之前
就解析 import table），缺了进程起不来，跑不到"启动后发现缺库再去下载"这一步。
所以它只能是构建输入。这条推理写在 [0003](0003-libav-in-process.md)。
## 版本迁移

允许的迁移：从本机已验证的版本升级到另一个**经过长时间使用**的版本。

不允许：跟随上游最新 release 自动升级；在没有任何实测的情况下换包。
理由很简单——FFmpeg 的小版本变化会改变 HLS 行为、探测默认值、编码器参数，
这些正是我们花了最多时间调的地方。换版本必须重新跑
[reference/measurements.md](../reference/measurements.md) 里的首帧对照。

升级步骤：

1. 在本机装上目标版本，用它跑一遍公网首帧对照（B 站 HEVC、抖音、斗鱼、虎牙各一）
2. 对比是否有退化，特别是转封装首帧和 HLS 播放列表解析
3. 改 `internal/ffmpeg` 里的版本号与 SHA-256
4. 在一台没有 FFmpeg 的干净机器上验首次准备流程

## 复查条件

- 上游长期使用中出现无法绕过的 bug（例如某类 HLS 播放列表解析错误）
- 需要新的编码能力（新增 AV1 硬件编码、新的容器支持）
- 下载源失效
