# 0005 冷启动不设启动层

**决定（2026-11-18）**：删掉 `internal/ui/splash.go`，冷启动第一帧就是应用本体
——顶栏、平台胶囊、分区栏、网格。封面没到时卡片显示一块静止的占位，封面到了
才淡入。没有最短停留、没有超时撤层、没有淡出。

## 为什么删

原来的启动层是四根呼吸竖条 + "ALIVE" + 一条扫光进度线，最少停 520ms，
最多 2500ms，然后 240ms 淡出。

三个问题：

1. **它会撒谎。** `splashReady()` 等首屏可视范围的封面都到位。mock 数据层没有
   封面，所以每次冷启动都会顶到 2500ms 上限，然后露出来的是——一排转圈的封面
   占位。用户盯着"正在载入"看了 2.5 秒，拿到的还是"正在载入"。一个兑现不了
   的承诺比没有承诺更糟。
2. **它锁输入。** 全屏 Box 盖住整棵树，这段时间点顶栏、点卡片都不响应。
   520 + 240 是最短锁死时间，慢网 2.5 秒。
3. **它不可测。** `time.Since(a.splashAt)` 走墙钟，`ui.NewTester` 的
   `tt.Advance` 推不动，所以整块没有一条测试。

再加上它画的是声波竖条——那是音乐播放器的语汇，和直播客户端、和
`resources/icon.png` 那个粉色的形象都没有关系。

## 换成了什么

- **首帧即应用。** `WindowOptions.BackgroundColor` 和 `theme.BgPrimary` 同值，
  第一帧画的就是终态布局，窗口从系统底色到第一帧没有接缝。
- **占位是静止的。** 封面位是一块 `BgTertiary` + 顶部受光边 + 极淡中心柔光，
  不转、不循环、不请求帧。静止是刻意的：一屏十几张卡一起转，每帧都在提醒
  "你还在等"；信息条上已经有主播名和标题，缺的只是画面。
- **动的那一下留给到达。** 当时写的是封面从 1.5% 的缩放进场（`ui.Smooth`）。
  后来量出来 `Enter` 根本不会播：占位和图片共用同一个元素身份。2026-11-21
  把这层死代码删了，封面改为原地换像素，见 [0010](0010-switch-content-still.md)。
- **读屏补一句。** 首屏空着时 `c.Announce("正在载入直播间")` 播一次
  （`bootAnnounced` 闸门防复读）。原来的启动层对读屏也是隐形的。

## 为什么不做成"更短的启动层"

任何"最少显示 N 毫秒"都是在给已经就绪的界面人为加延迟。Doherty 阈值说的是
反馈要快，不是等待要好看。数据没到时界面本来就有占位，不需要另一层来演示
"我在努力"。

## 怎么验的

`internal/ui/cold_start_test.go` 四条，都在改动前的代码上先跑红：

- `TestColdStartShowsTheShell`：冷启动第一帧顶栏不是一块纯底色（像素）。
- `TestColdStartAcceptsInput`：启动过程中点平台 tab 就换平台。
- `TestColdStartAnnouncesTheWaitOnce`：播报一次，四帧后仍然只有一条。
- `TestCoverPlaceholderDoesNotAnimate`：`coverArt` 里不许出现 `Loop` 或 `spinnerTint`
  （静态扫描，防止转圈被加回来）。

前两条在旧代码上要先把启动层打开才红——`NewMockApp` 本来不走那一条，这也正是
为什么旧启动层从来没被测过。

## 什么情况下重做

如果实测冷启动到首帧的空白超过 ~300ms 且无法从数据预取上压缩，那时该做的是
首帧内容（骨架布局、上次的封面缓存），不是盖一层遮罩。

实测（2026-11-18，见 [measurements.md](../reference/measurements.md#冷启动2026-11-18)）：
窗口到首帧 8–19ms，列表 256ms，封面 542ms，热启动与冷启动持平——瓶颈在平台接口，
不在本地缓存。首帧本身没有空白需要补。
