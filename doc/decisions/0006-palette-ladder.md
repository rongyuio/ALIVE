# 0006 配色由参数生成，对比度写成测试

**决定（2026-11-18）**：`internal/theme` 的六套配色不再手写二十个十六进制。
每套只声明六个输入（地的 Oklch、四档文字的明度、强调色），其余由
`build()` 推导：表面沿一条明度阶梯抬升，文字沿另一条收敛，强调色按对比度
自动算出「当字用」和「当线用」两个版本。`contrast_test.go` 把 WCAG 的线
钉在 `make check` 里。

## 为什么要动

不是审美问题，是账：

- **六套配色里有四套是复制的。** `ember`（琥珀·夜）的地是暖黑 `#100c08`，
  卡片却是 `#14161b` 那块冷蓝黑——和 `signal` 一模一样。`mono`（黑白灰）
  的卡片也是 `#14161b`，一个无彩色配色里混进了带色相的卡片。两个色相相差
  一百多度，明度阶梯查不出来，色相查得出来（`TestSurfaceFamilySharesHue`）。
- **`TextMeta` 在每一套里都至少挂一个表面。** 19 对低于 4.5:1，最低的
  `mono` 卡片上只有 3.82:1。人眼看不出来，低视力用户看得出来。
- **浅色主题的品牌色是隐形的。** `daylight` 的青柠 `#d8ff4f` 压在白卡片上
  ≈1.1:1。作为填充按钮，里面的黑字救得回来；作为配色面板的选中描边、
  灵动岛的呼吸环，它在白底上根本不存在。
- **令牌没人管。** 35 个颜色令牌里 5 个零引用（`SidebarBg`、`AccentGlow`、
  `StatusLive`、`OverlayInkStrong`、`PlayerGlass`），`internal/ui` 里还有
  96 处直接写的 `ui.RGBA/ui.Hex`。

## 换成了什么

| | |
|---|---|
| `palette.go` | `spec`（六个输入）+ `build()`。表面阶梯、边框、文字、强调色全部推导 |
| 强调色 | 拆成三个用途：`Accent`（填充）、`AccentInk`（当字，≥4.7:1）、`AccentLine`（当线，≥3.2:1）。后两个由 `withContrast` 沿明度推出来，色相彩度不动 |
| 强调色上的字 | 深墨和近白两个候选，取对比度高的那个，不按 L 猜 |
| `theme.go` | 包级颜色不再写字面量，`init()` 调一次 `Apply`。一份颜色只有一个来源 |
| 死令牌 | 删了 5 个 |
| 用对的地方 | 配色面板的选中描边、灵动岛的呼吸环改用 `AccentLine`（浅色主题里第一次看得见） |

## 验证

`internal/theme/contrast_test.go` 五条，都在改动前跑红：

- `TestPaletteContrast`：主/次文字在每个表面 ≥4.5，三级/元数据在平静表面
  ≥4.5，`AccentInk`/`AccentText` ≥4.5，`AccentLine` 作为图形 ≥3.0。
  改动前 19 对失败，现在 0。
- `TestPaletteLadderIsMonotonic`：地 < 卡片 < 三级填充（深色），文字四档反向。
- `TestSurfaceFamilySharesHue`：地、卡片、三级填充的 Oklab 色相差 ≤20°。
  改动前 `mono` 和 `ember` 被抓出来。
- `TestDefaultGroundMatchesWindow`：读 `main.go` 的 `BackgroundColor`，
  和默认配色的地逐字节比对——首帧和窗口底色不能有缝。
- `TestAccentLineIsVisible`：当线用的强调色在两种底上 ≥3:1。

视觉验收：六套配色各起一次真窗口截图（`.tmp/probes/color/e2e/`），
外加浅色主题下打开配色面板一张，确认选中描边可见。

## 留着没做的

- **播放页控制条的真玻璃。** `glass.Glass` 采样的是同一个窗口里画在它下面的
  像素，播放页控制条下面正好是活动画面，是这个方案里唯一值得用材质的地方。
  现在控制条是 `rgba(10,11,13,.92)` 硬压。原 `theme.PlayerGlass` 令牌已删
  （值 `ui.RGBA(10, 11, 13, 0.92)`），要做时重新加回来并改成材质。
  前置：Inspector 量改造前后帧耗时、`ReduceTransparency` 下退回实色。
- **强调色的使用面积。** 这次只保证它"看得见"，没有削减它在界面里出现的
  次数。哪些地方该让位给中性色，要等这版配色在真实页面上跑一段再说。
- **`internal/ui` 的 96 处字面量。** 内容色（弹幕颜色）本来就该是自由的，
  表面色不该。分类要一处一处看，不是一次性替换。
- **`c.Preferences().HighContrast`。** 还没接。接了之后边框和次级文字要再深
  一档，这条会和对比度测试互相牵制，值得单独做。

## 补完的四件事（2026-11-19）

**高对比。** `c.Preferences().HighContrast` 现在会进到自绘的颜色里：`SetHighContrast`
每帧由 Shell 设置，`Apply` 换成 `hcPalettes` 里的对应版本。高对比不是"同一套色再加黑边"，
而是换一条阶梯——次级往正文靠一半、三级升到原来的次级、描边升成强描边，
层级从"明度拉开"改成"字重和字号拉开"。`TestHighContrastPaletteContrast` 要求正文
≥7:1、其余不低于普通模式，`monotonic` 也一起覆盖。

**浅色的地压深了一档。** 地从 L≈0.958 降到 0.940，卡片仍然是纯白。之前卡片和地只差
3%，分层全靠 1px 描边；现在卡片是浮在页面上的。这是六套里唯一改了观感的一处。

**色板预览改成「地 / 字 / 强调」。** 原来是「地 / 表面 / 强调」，浅色主题里前两块
都是白，预览等于只说了一半。现在中间那块是正文色，一眼能看出这套配色的对比关系。

**画面上的墨收进令牌。** `ui.RGBA(255,255,255,0.05/0.08/0.12/0.15/…)` 这类在
播放器和弹幕面板里散着写的白色，收成 `MediaRow / MediaRowLine / MediaHair /
MediaTrack / MediaText / MediaTextDim / MediaPanel / MediaScrim`。它们**不跟配色走**：
浅色主题里把面板刷白，压在视频上的字就没了。33 处替换，视觉零变化。

## 材质：只给一处真玻璃

控制条的底色从 `rgba(9,10,12,.55)` 换成 `glass.Glass{Style: Regular, Tint: playerBarBg}`。
这是全应用唯一"下面真的有画面"的 chrome，也是这次唯一值得上材质的地方。

- 先试了 `Clear`：它几乎不模糊，换上去和实色没有区别，白付一次采样。
- 再试了不带 tint 的 `Regular`：浅色主题下玻璃被提亮成一块白板，白字读不出来。
- 最后是 `Regular` + 原来的深色 tint：模糊真的发生，颜色的压暗还在。

验证方式：真流（B 站 1080P 原画）播起来截图，玻璃区能看到画面透上来。
**副产物**：`TestPlayerIconsShareInkBand` 挂了——它在控制条里扫亮像素量图标墨迹，
玻璃让背后的亮画面透了进来。这条测试量的是图标几何，不是材质，所以在测试里
把 `ReduceTransparency` 打开再量。它挂掉这件事本身，反过来证明玻璃确实采样到了画面。

没做和没测的：

- **GPU 成本没有数字。** `mygo-automation` 读不到帧耗时，Inspector 只在开发构建里，
  外部拿不到；CPU 时间也测不出来（我试了两个脚本，拿到的是空值，就没往文档里写）。
  要数字得在 app 里加临时探针读帧间隔——和冷启动那套一样，但这次没做。
- **`ReduceTransparency` 只验证了代码路径**（关掉透明时回到 `Background(playerBarBg)`），
  没在系统设置里真的关一次透明度看截图。
- **缓冲中 / 降档提示这两个 30 高的胶囊**还是实色：那个尺寸的玻璃在视觉上等于实色，
  不值得多一次采样。

## 强调色：没有降到 8 处

方案里说"压到 8 处以内"，实际数了一遍 30 处引用，绝大多数是**状态**：四个滑块、
三个开关、两个 tab 选中、三个主操作。把状态色去掉，选中态就没了。

改的是**装饰性**的那一处：卡片 hover 的播放圆钮从青柠底换成深色遮罩 + 白三角。
封面本来就是彩色的，鼠标扫过一排卡片时每张都亮一次青柠，强调色就不强调了。
首页静止状态现在只有两处青柠：当前平台、当前分区。

真正的收法应该是"每屏可见的强调色 ≤3"，而不是"代码里 ≤8 处"。前者需要一张一张截图
数，后者会逼着人去删状态色。这次先改到两处，剩下的等真实页面反馈再说。

## 第二处玻璃与剩下的字面量（2026-11-19）

弹幕设置、关键词面板、清晰度下拉也换成了同一块玻璃（`mediaPanel`）：它们浮在
视频上，是第二类"下面真有内容"的地方。tint 用 0.72 而不是实色的 0.88——0.88
会把模糊全遮掉，玻璃就只是贵一点的实色。

`internal/ui` 的字面量从 96 降到 26。剩下的分两类：视频上的遮罩/阴影（每个位置
本来就该不一样），和弹幕颜色（用户选的，不该进主题）。

**帧成本**：用 MyGo 自带的 `MYGO_FRAME_STATS=1 MYGO_UNCAPPED=1` 量了，
两种构建的差异小于同一构建两次运行之间的差异，都远低于 16.7ms。数字和量法在
[measurements.md](../reference/measurements.md#帧成本怎么量2026-11-19)。
上一节写的"没有测量手段"是错的——手段一直有，只是我不知道。

**强调色没有继续削。** 弹幕面板里的四个滑块、两个开关、数值文字仍然是青柠：
它们是值的指示，去掉之后面板就没有可读的状态了。首页静止态保持在两处。

## 顶栏的两种底色（2026-11-19）

截图里同一条顶栏，左边的平台轨道是白的，右边的窗口按钮是灰的。原因是一行写死的
`ui.Hex("#ffffff")`：浅色主题下给轨道单独刷白，绕过了调色板——而新配色的地是
`#eaebed`、卡片才是白的，于是轨道比地亮、和右边的容器对不上。

轨道和窗口按钮本来就是同一类容器（装一排可点的东西），现在都用
`FillQuaternary + Border(1, Border)`。浅色主题里白色只留给卡片。

## 阴影阶梯

单层阴影只能在"看不见"和"像贴纸"之间选：`0 22 56 -22` 在白底上几乎不存在，
压重了又没有接触感。改成两级：

| 令牌 | 用途 | 几何 |
|---|---|---|
| `ShadowPanel` | 下拉、气泡 | 0 22 56 -22 |
| `ShadowModal` | 面板、登录层、灵动岛 | 0 38 72 -30 |
| `ShadowContact` | 每一层的接触影 | 0 4–6 px，近实 |

九处浮层和灵动岛统一走这一套。浅色的环境光从 0.26/0.28 降到 0.18/0.22，
靠接触影补回"贴着"的感觉；灵动岛原来按深浅主题各写死一对手调值，现在是同一套。

视频上的阴影不在这条链上（它们不跟主题变），单独有 `MediaShadow` /
`MediaShadowStrong` 两个令牌。

## 顶栏托盘：地 / 托盘 / 卡片三等分（2026-11-19）

截图里同一条顶栏，左轨道有描边、工具组没有、窗口按钮有，中间的灵动岛又是白的。
这不是配色不好看，是**同一类容器有四套配方**。

根因是一个令牌干了两件事。`FillQuaternary` 是「卡片上的浅填充」，明度台阶相对
卡片定；被顶栏托盘拿去放在 `BgPrimary` 上之后，浅色主题只剩 1.9 个 L*，
于是有人补了 1px 描边——形状从此是线画的。深色主题里同一个令牌又跑到地上面，
托盘从「凹槽」变成「凸片」。

换成 `SurfaceChrome`：地和卡片在 **L\*** 上的中点，由 `midpointL` 二分推导。
三档阶梯现在是 地 → 托盘 → 卡片，六套配色两边各 2.4–3.6 个 L\*，深色等分、
浅色等分。数字和规则在 [palette-ladder.md](../reference/palette-ladder.md)。

同时做了三件事：

- **静态表面撤掉装饰描边**：平台轨道、工具组、窗口按钮组、分区面板、关注页面板、
  分区搜索、顶栏搜索、关注页搜索、同步面板的页签、顶栏骨架。卡片本来就没有。
- **删掉顶栏那根竖直分隔线**：窗口按钮有托盘之后，它是第二道边。
- **三组托盘统一内高 34**：之前轨道 34、图标按钮 38、窗口按钮 34，窄屏 36/34/32，
  同一条 64 高的栏里三个盒子三种高度。

两条测试兜底，都在改动前跑红：

- `internal/theme/ladder_test.go` 的 `TestChromeSitsBetweenGroundAndCard`：地 < 托盘 < 卡片，
  两边 ≥2.3 个 L\*，且等分（下上差 ≤0.5）。
- `internal/ui/container_test.go`：
  - `TestStaticSurfacesHaveNoStroke` 扫源码，`BgSecondary`/`FillQuaternary` + `Border(1, theme.Border)`
    直接报行号；例外写 `// container: allow 理由`。
  - `TestNavbarTraysUseOneSurface` 在 100% 和 150% 缩放下扫顶栏中线，长色段只能落在
    地面/托盘/滑块里，且托盘色段至少三段。

**没做**：功能性描边还没有 3:1 的版本。未订阅的「订阅分区」只有一圈 1.27:1 的线，
按 WCAG 2.2 §1.4.11 它不能单独承担「这里可点」。这是下一件事，不和装饰边混在一起做。
